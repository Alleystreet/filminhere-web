# Security Baseline

Complete this before release. Add evidence or a reason when an item does not apply.

- [ ] Privileged accounts use named identities, least privilege, and MFA where supported.
- [ ] Registrar, DNS, email, cloud, payment, and recovery accounts have verified owners.
- [ ] Secrets are outside code, prompts, logs, screenshots, and repositories.
- [ ] Supported versions and security updates are in place.
- [ ] Public attack surface is minimized; origin/admin access is restricted where practical.
- [ ] Security-relevant logging and alerts reach a responsible owner without exposing secrets.
- [ ] Backup, restore, rollback, and incident contacts are documented and tested.
- [ ] Stale accounts, unused extensions, and unnecessary integrations are removed.
- [ ] Material vulnerabilities are fixed or documented as owned, dated warnings.
