## Demonstrated defects and corrections

1. `POST /api/booking/create` accepted parsed JSON without checking its root shape.
   An authenticated body of `null` threw before a structured response. The handler
   now rejects null, arrays and scalar roots with HTTP 400 before privileged access.
2. Listing lookup and booking insert failures returned raw database messages to
   the browser. Both paths now return fixed messages that omit database details.
   Existing authentication, listing ownership and status assignment are retained.

The isolated suite executes the actual TypeScript handler after removing type
annotations, with in-memory framework/database adapters and no network or real
credentials. Before the correction, seven assertions failed, including the null
exception and both diagnostic disclosures. Afterward all 14 cases passed. The
suite also verifies authentication rejection, malformed JSON, missing config,
date rejection, absent listings, canonical listing identity and forged fields.

The handler change is separate commit
`9789717d1f8e8953a9a70f4982349240ad92a770`. The booking workflow and general Verify
workflow use Node.js 24. `npm test` now runs the date checks, handler cases, guard
self-test and all 20 existing preflight/lifecycle checks.
